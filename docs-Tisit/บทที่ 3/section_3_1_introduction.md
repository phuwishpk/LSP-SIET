# 3.1 กล่าวนำ

บทนี้นำเสนอการวิเคราะห์และออกแบบระบบ KMITL AI Workspace และ SIET Space โดยใช้แนวทางทางวิศวกรรมซอฟต์แวร์เพื่อแปลงความต้องการของผู้ใช้ให้เป็นสถาปัตยกรรม กระบวนการทำงาน โครงสร้างข้อมูล และส่วนติดต่อที่สามารถนำไปพัฒนาและตรวจสอบได้ เนื้อหาครอบคลุมการทำงานร่วมกันของผู้ใช้สามบทบาท ได้แก่ ผู้ดูแลระบบ ผู้สอน และนักศึกษา ตลอดจนขอบเขตความรับผิดชอบของระบบย่อยที่เกี่ยวข้องกับการจัดการบัญชีและสิทธิ์ การจัดการรายวิชาและคลังความรู้ ระบบคอมมูนิตี้และแต้มสะสม และบริการปัญญาประดิษฐ์

การกำหนดสถาปัตยกรรมเริ่มจากการพิจารณาภาพรวมการเชื่อมต่อระหว่างส่วนติดต่อผู้ใช้ ส่วนประมวลผล API และบริการจัดเก็บข้อมูล โดยระบบจัดวางบริการหลายชนิดบน Docker Compose และแบ่งโค้ดเป็นโมดูลตามหน้าที่ แม้ว่าบางแอปพลิเคชันจะให้บริการผ่านคอนเทนเนอร์แยก แต่ API หลักและโมดูลแพลตฟอร์มหลายส่วนยังทำงานร่วมกันในกระบวนการของบริการหลัก จึงอธิบายระบบในลักษณะสถาปัตยกรรมแบบโมดูลาร์และหลายบริการ แทนการถือว่าทุกโมดูลเป็นไมโครเซอร์วิสที่แยก deploy อย่างสมบูรณ์

จากสถาปัตยกรรมดังกล่าวจึงกำหนดแผนภาพการไหลของข้อมูล (Data Flow Diagram: DFD) ตั้งแต่แผนภาพบริบทและ DFD ระดับ 1 จนถึงรายละเอียดของกระบวนการคอมมูนิตี้และกระบวนการปัญญาประดิษฐ์ในระดับ 2 รวมทั้งใช้แผนภาพยูสเคสแสดงปฏิสัมพันธ์ระหว่างผู้ใช้กับระบบย่อยและการกำหนดสิทธิ์ตามบทบาท หลักการควบคุมการเข้าถึงตามบทบาท (Role-Based Access Control: RBAC) ถูกประยุกต์ร่วมกับการตรวจสอบขอบเขตทรัพยากร เช่น การกำหนดผู้มีสิทธิ์จัดการห้องเรียนและคลังเอกสารรายวิชา

การออกแบบระบบคอมมูนิตี้เชื่อมโยงแนวคิดการจัดการความรู้และการมีส่วนร่วมทางสังคมเข้ากับกลไกเกมมิฟิเคชันแบบสะสมและใช้แต้ม โดยบันทึกธุรกรรมแต้มเพื่อให้ตรวจสอบการเปลี่ยนแปลงได้ ส่วนระบบ KMITL RAG AI ประยุกต์กระบวนการ Retrieval-Augmented Generation (RAG) เพื่อค้นคืนเนื้อหาจากเอกสารและใช้เป็นบริบทสำหรับสร้างคำตอบ พร้อมจำกัดขอบเขตข้อมูลที่ค้นคืนและแสดงการอ้างอิงแหล่งที่มา การออกแบบส่วนติดต่อยึดผู้ใช้เป็นศูนย์กลาง (User-Centered Design: UCD) โดยพิจารณาความแตกต่างของบทบาท การตอบสนองต่อขนาดหน้าจอ และความต่อเนื่องของประสบการณ์ใช้งานระหว่างแอปพลิเคชัน

ในด้านข้อมูล ระบบใช้สถาปัตยกรรมฐานข้อมูลแบบผสมผสาน โดยใช้ MariaDB สำหรับข้อมูลบัญชี ธุรกรรม และข้อมูลเชิงสัมพันธ์ของคอมมูนิตี้ ใช้ SurrealDB สำหรับข้อมูลสมุดความรู้ แหล่งเอกสาร เวกเตอร์ และสถานะการสร้างควิซหรือแผนการเรียน และใช้ Redis สนับสนุนการทำแคช ทั้งนี้มีการเชื่อมโยงระหว่างฐานข้อมูลด้วยรหัสอ้างอิงเชิงตรรกะที่จัดการโดยแอปพลิเคชัน นอกเหนือจากการจัดเก็บไฟล์และบริการ PocketBase ที่ประกอบอยู่ในระบบสำหรับแอปพลิเคชันแผนการเรียนแบบแยก

หัวข้อถัดไปจึงเรียงลำดับจากสถาปัตยกรรมและการไหลของข้อมูล การกำหนดยูสเคสและสิทธิ์ การออกแบบคอมมูนิตี้และกลไกแต้ม การออกแบบระบบ RAG ส่วนติดต่อผู้ใช้ และสคีมาฐานข้อมูลตามลำดับ จากนั้นจึงเชื่อมโยงรายละเอียดเหล่านี้กับการพัฒนาโมดูล การตรวจสอบการทำงาน และการทดสอบการประสานงานระหว่างส่วนประกอบ เพื่อให้การนำเสนอการออกแบบสอดคล้องกับโครงสร้างที่ปรากฏในระบบจริง
