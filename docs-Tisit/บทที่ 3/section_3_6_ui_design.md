# 3.6 การออกแบบส่วนติดต่อผู้ใช้งาน

## 3.6.1 แนวทางการออกแบบโดยมีผู้ใช้เป็นศูนย์กลาง

การออกแบบส่วนติดต่อผู้ใช้งาน (User Interface: UI) ใช้หลักการออกแบบโดยมีผู้ใช้เป็นศูนย์กลาง (User-Centered Design: UCD) โดยพิจารณางานที่ผู้ใช้แต่ละบทบาทต้องดำเนินการและจัดกลุ่มความสามารถตามบริบทการใช้งาน นักศึกษาสามารถเข้าถึงฟีด ห้องเรียน คลังส่วนบุคคล และบริการ AI ขณะที่ผู้สอนและผู้ดูแลเห็นเมนูควบคุมเพิ่มเติมตามสิทธิ์ที่ได้รับ การแสดงเมนูตามบทบาทช่วยลดความซับซ้อนในการใช้งาน แต่ไม่ได้ใช้แทนการตรวจสิทธิ์ที่ API

ระบบใช้ Design System ร่วมกันระหว่างส่วนต่าง ๆ ประกอบด้วยองค์ประกอบ UI ที่นำกลับมาใช้ซ้ำ รูปแบบปุ่ม การ์ด แบบฟอร์ม เมนูนำทาง ฟอนต์ และตัวแปรสีซึ่งกำหนดเป็น design tokens การใช้ระบบออกแบบร่วมช่วยรักษาความสม่ำเสมอขององค์ประกอบและลดความแตกต่างระหว่างหน้าชุมชน หน้าคลังความรู้ และหน้าบริการ AI ขณะเดียวกัน layout ปรับตามขนาดหน้าจอและเปลี่ยนการนำทางบางส่วนเป็นเมนูแบบแผงเลื่อนเมื่อพื้นที่หน้าจอจำกัด

## 3.6.2 โครงสร้างหน้าจอหลัก

หน้าคอมมูนิตี้บนจอขนาดใหญ่จัดวางเป็นสามคอลัมน์ตามรูปที่ 0.13 ได้แก่

1. **แถบนำทางด้านซ้าย (Left Navigation Bar):** แสดงฟีด ห้องหรือรายวิชาที่เข้าร่วม มุมมองโพสต์ที่บันทึกไว้ สื่อการสอน และทางลัดไปยังหน้าที่เกี่ยวข้อง
2. **พื้นที่เนื้อหาหลัก (Main Content Feed):** แสดงรายการโพสต์ เครื่องมือค้นหา และส่วนสร้างเนื้อหา โดยผู้ใช้สามารถกรองฟีดตามรายวิชา ประเภท หรือมุมมองที่เลือก
3. **แผงสถานะด้านขวา (Right Gamification/Status Panel):** แสดงข้อมูลประกอบการใช้งาน เช่น สถานะแต้ม กฎการสะสมและใช้แต้ม หรือข้อมูลที่ช่วยให้ผู้ใช้เข้าใจกลไกการมีส่วนร่วม

ความกว้างคอลัมน์ด้านซ้ายและขวากำหนดไว้ประมาณ 260 และ 340 พิกเซลตามลำดับ โดยพื้นที่กลางขยายตามขนาดหน้าจอ เมื่อหน้าจอแคบลงระบบเปลี่ยนเป็นการจัดวางคอลัมน์เดียวและเรียกแถบนำทางผ่านเมนูแบบ Sheet เพื่อให้เนื้อหาหลักยังอ่านได้โดยไม่ต้องเลื่อนแนวนอน

## 3.6.3 แถบนำทางร่วมและความแตกต่างตามบทบาท

ส่วนประกอบ Navbar ที่ใช้ร่วมกันทำหน้าที่เป็นจุดเชื่อมการนำทางระหว่างคอมมูนิตี้ KMITL RAG, Quiz และ Roadmap พร้อมแสดงข้อมูลบัญชี การแจ้งเตือน และกระเป๋าแต้มตามบริบท แถบนำทางรองรับรูปแบบ responsive โดยปรับรายการหรือตัวควบคุมให้เหมาะกับหน้าจอขนาดเล็ก การใช้ Navbar ร่วมช่วยรักษารูปแบบการใช้งานและลดความจำเป็นที่ผู้ใช้ต้องเรียนรู้รูปแบบนำทางใหม่ในแต่ละแอป

การแยกบทบาทผู้ใช้ในส่วนติดต่อดำเนินการผ่านรายการเมนู ป้ายกำกับ และชุดคำสั่งที่ปรากฏ เช่น หน้าจัดการห้องและเครื่องมือดูแลเนื้อหาสำหรับผู้มีสิทธิ์ ไม่ได้อาศัยสีเป็นตัวบ่งชี้สิทธิ์เพียงอย่างเดียว จากการตรวจสอบธีมที่ใช้งานจริง ระบบใช้ชุดสี SIET Pink ร่วมกันในพื้นที่หลักและคอมมูนิตี้ ไม่พบชุดสีเฉพาะสำหรับนักศึกษาและชุดสีสุภาพแยกต่างหากสำหรับผู้สอน การอธิบายการออกแบบจึงควรระบุว่าความแตกต่างของบทบาทสื่อผ่านโครงสร้างการนำทางและการควบคุมการใช้งาน ขณะที่โทนสีหลักยังคงเป็นระบบเดียวกัน

องค์ประกอบ UI แสดงข้อมูลสถานะและผลการดำเนินการ เช่น ยอดแต้ม ข้อความแจ้งเตือน ความคืบหน้าการประมวลผลเอกสาร และผลการสร้างเนื้อหา AI การให้ข้อมูลย้อนกลับดังกล่าวทำให้ผู้ใช้ทราบว่าระบบกำลังดำเนินการสำเร็จ ล้มเหลว หรือจำเป็นต้องปรับข้อมูลนำเข้า ซึ่งสอดคล้องกับเป้าหมายของ UCD ในด้านความเข้าใจง่ายและการควบคุมการทำงานของผู้ใช้
