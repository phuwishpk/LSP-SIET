# 3.9 การบูรณาการและพัฒนาระบบ KMITL RAG AI

KMITL RAG AI เป็นระบบถาม–ตอบที่นำเอกสารและองค์ความรู้ในคลังของแพลตฟอร์มมาใช้ประกอบการสร้างคำตอบ กระบวนการทำงานเชื่อมโยงส่วนติดต่อผู้ใช้งาน บริการ API ของแพลตฟอร์ม การจัดการเอกสารและการค้นคืน ตลอดจนแบบจำลองภาษาขนาดใหญ่ (Large Language Model: LLM) ระบบใช้ MariaDB สำหรับข้อมูลกำกับเอกสารและประวัติธุรกรรมที่เกี่ยวข้องกับผู้ใช้ และใช้ SurrealDB ซึ่งเป็นฐานข้อมูลของ Open Notebook สำหรับจัดเก็บสมุดบันทึก แหล่งข้อมูล และเวกเตอร์ของข้อความที่ผ่านการฝังเวกเตอร์

## 3.9.1 สถาปัตยกรรมการเชื่อมต่อและไปป์ไลน์การนำเข้าเอกสาร

กระบวนการนำเข้าเอกสารเริ่มจากผู้ใช้งานเลือกขอบเขตคลังความรู้และส่งไฟล์ ลิงก์ หรือข้อความเข้าสู่ระบบ บริการจัดการคลังความรู้สร้างรายการกำกับเอกสารในตาราง `library_documents` ของ MariaDB โดยระบุเจ้าของ ขอบเขต (`course` หรือ `personal`) ห้องที่เกี่ยวข้อง สมุดบันทึก ชื่อเอกสาร ประเภทข้อมูล ตำแหน่งไฟล์ และสถานะเริ่มต้นเป็น `processing` ตารางดังกล่าวยังเก็บ `source_id`, จำนวนชิ้นข้อความ จำนวนอักขระ และสถานะผลการประมวลผล เพื่อให้ส่วนติดต่อผู้ใช้งานติดตามสถานะของเอกสารได้

หลังจากบันทึกข้อมูลกำกับแล้ว ระบบแปลงเนื้อหาเอกสารให้อยู่ในรูปข้อความ โดยเอกสารไฟล์และ URL ผ่านกระบวนการสกัดเนื้อหาของส่วนประกอบ `content_core` และกำหนดรูปแบบผลลัพธ์เป็น Markdown ส่วนข้อความที่ผู้ใช้ป้อนโดยตรงจะเข้าสู่กระบวนการโดยไม่ต้องอ่านไฟล์ซ้ำ ระบบจำกัดความยาวข้อความที่นำเข้าและแจ้งสถานะผิดพลาดหากไม่สามารถสกัดเนื้อหาได้หรือไม่พบข้อความ เช่น กรณีเอกสาร PDF ที่เป็นภาพสแกนและยังไม่ได้ผ่าน OCR สำหรับไฟล์สื่อบางประเภทซึ่งไม่สามารถแปลงเป็นข้อความ ระบบจัดเก็บไฟล์ไว้ให้ดาวน์โหลดและกำหนดสถานะพร้อมใช้งานโดยไม่สร้างเวกเตอร์

เมื่อได้ข้อความแล้ว ระบบสร้างระเบียน `source` ใน SurrealDB โดยเก็บชื่อ เนื้อหาฉบับเต็ม และข้อมูลประกอบ จากนั้นเชื่อมโยงแหล่งข้อมูลเข้ากับ `notebook` ผ่านความสัมพันธ์ `reference` ทำให้สามารถค้นคืนเอกสารภายในสมุดบันทึกที่กำหนดได้ การเชื่อมโยงนี้มีความสำคัญต่อการแยกขอบเขตของคลังส่วนบุคคลและคลังรายวิชา รวมถึงการจำกัดผลการค้นคืนตามสิทธิ์ของผู้ใช้งาน

**การแบ่งข้อความและสร้างเวกเตอร์** ระบบตรวจจับชนิดเนื้อหาก่อนเลือกวิธีแบ่งข้อความ หากเป็น Markdown จะพยายามรักษาโครงสร้างหัวข้อ หากเป็น HTML จะใช้โครงสร้างส่วนหัวเป็นแนวทาง และหากเป็นข้อความทั่วไปจะใช้การแบ่งแบบลำดับชั้นโดยพิจารณาจุดแบ่ง เช่น ย่อหน้า บรรทัด และเครื่องหมายวรรคตอน ความยาวของชิ้นข้อความประเมินด้วยจำนวนโทเคน มีการแบ่งข้อความซ้ำเมื่อชิ้นที่เกิดจากหัวข้อมีขนาดใหญ่เกินกำหนด และกรองชิ้นที่ว่างหรือมีขนาดเล็กมากเมื่อยังมีชิ้นอื่นที่เหมาะสม กระบวนการนี้มีวัตถุประสงค์เพื่อรักษาบริบทเชิงโครงสร้างของเอกสาร พร้อมควบคุมขนาดข้อมูลที่ส่งไปสร้างเวกเตอร์

ระบบส่งชิ้นข้อความไปยังฟังก์ชันสร้าง Embedding ของ Open Notebook ซึ่งเลือกผู้ให้บริการตามการตั้งค่าแบบจำลองที่ระบบกำหนด จากนั้นบันทึกข้อมูลแต่ละชิ้นในตาราง `source_embedding` ของ SurrealDB โดยเชื่อมโยงกับ `source` และจัดเก็บลำดับชิ้น เนื้อหาข้อความ และเวกเตอร์ที่ได้ หากจำนวนเวกเตอร์ที่สร้างไม่ตรงกับจำนวนชิ้นข้อความ ระบบถือว่ากระบวนการไม่สมบูรณ์และบันทึกสถานะเอกสารเป็น `failed` เมื่อประมวลผลสำเร็จ ระบบปรับปรุง `library_documents.status` เป็น `ready` พร้อมบันทึกจำนวนชิ้นข้อความและจำนวนอักขระ การประมวลผลซ้ำจะลบเวกเตอร์เดิมของแหล่งข้อมูลนั้นก่อนสร้างชุดใหม่ เพื่อลดการคงเหลือของข้อมูลเวกเตอร์จากการนำเข้าครั้งก่อน

## 3.9.2 กระบวนการสืบค้นและสังเคราะห์คำตอบ

เมื่อผู้ใช้ส่งคำถาม ระบบเริ่มจากตรวจสอบขอบเขตความรู้ที่เลือก เช่น คลังรายวิชา คลังส่วนบุคคล เอกสารเฉพาะ หรือสมุดบันทึก จากนั้นบริการตรวจสอบสิทธิ์การอ่านและแปลงขอบเขตเป็นรายการ `notebook` และ `source` ที่อนุญาตให้ค้นคืน การกำหนดขอบเขตดังกล่าวเป็นเงื่อนไขสำคัญของการรักษาความเป็นส่วนตัว โดยเมื่อผู้ใช้ระบุขอบเขตเฉพาะ ระบบจะไม่ขยายการค้นหาไปยังคลังส่วนกลางโดยอัตโนมัติหากไม่พบข้อมูลในขอบเขตนั้น

ระบบสร้าง Embedding สำหรับคำถามด้วยแบบจำลอง Embedding ที่ตั้งค่าไว้ และใช้การค้นหาความคล้ายคลึงแบบโคไซน์ (Cosine Similarity) ระหว่างเวกเตอร์คำถามกับเวกเตอร์ใน `source_embedding` โดยเรียงลำดับผลลัพธ์จากค่าความคล้ายคลึงสูงไปต่ำ และใช้ค่าความคล้ายคลึงขั้นต่ำเพื่อกรองผลที่ไม่เกี่ยวข้อง การค้นหาแบบจำกัดสมุดบันทึกจะใช้ความสัมพันธ์ระหว่าง `notebook` กับแหล่งข้อมูลเป็นขอบเขตของคำสั่งค้นหา นอกจากนี้ ระบบดึงผลลัพธ์เกินจำนวนที่ต้องการในขั้นต้นและตัดข้อความซ้ำด้วยลายนิ้วมือของเนื้อหา เพื่อให้ได้บริบทที่หลากหลายและลดกรณีที่เอกสารมีเวกเตอร์ของชิ้นเดียวกันซ้ำหลายรายการ

**การจัดสรรบริบทและการสังเคราะห์คำตอบ** ในเส้นทางถาม–ตอบของ KMITL RAG AI ระบบคัดเลือกข้อความที่เกี่ยวข้องสูงสุดไม่เกิน 6 ชิ้นตามค่าเริ่มต้น กำหนดขนาดข้อความแต่ละชิ้นไม่เกิน 1,800 อักขระ และจำกัดบริบทโดยรวมไว้ที่ 14,000 อักขระตามค่าตั้งเริ่มต้น กรณีเลือกเอกสารเฉพาะ ระบบอาจเพิ่มบทสรุปของเอกสารเพื่อให้บริบทมีทั้งรายละเอียดและภาพรวม จากนั้นกำหนดหมายเลขอ้างอิงให้ข้อความที่คัดเลือกและประกอบเป็นพร้อมต์ ซึ่งประกอบด้วยขอบเขตองค์ความรู้ ข้อความที่ค้นคืน ประวัติการสนทนาที่เกี่ยวข้อง และคำถามของผู้ใช้

ส่วนประกอบ Open Notebook ยังมี `ContextBuilder` สำหรับการสนทนาที่ใช้บริบทจากสมุดบันทึกหรือแหล่งข้อมูลโดยตรง โดยประเมินขนาดบริบทเป็นจำนวนโทเคนก่อนส่งให้แบบจำลอง และปรับลดเนื้อหาหรือจัดสรรงบประมาณให้ข้อมูลสรุปเมื่อเอกสารมีขนาดใหญ่ ในการสนทนากับแหล่งข้อมูล ระบบเรียก `build_source_context` โดยกำหนดเพดานบริบทสูงสุด 50,000 โทเคนตามค่าที่ส่งจากกราฟการสนทนา และเมื่อเนื้อหาเกินเพดานจะกันงบประมาณส่วนหนึ่งไว้สำหรับข้อมูลสรุปก่อนตัดทอนข้อความต้นฉบับ อย่างไรก็ตาม เส้นทาง API ถาม–ตอบ KMITL RAG AI ที่ใช้ในวิดเจ็ตชุมชนมีขั้นตอน `retrieve` และขีดจำกัดบริบทตามจำนวนอักขระดังกล่าวแยกต่างหาก จึงไม่ควรตีความว่าการถามทุกประเภทใช้ `ContextBuilder` ตัวเดียวกัน

พร้อมต์ที่ประกอบแล้วถูกส่งผ่านชั้นนามธรรมของแบบจำลอง โดยส่วนประกอบ `grounding` เรียก `model_manager` เพื่อเลือกแบบจำลองที่ผู้ดูแลระบบกำหนดหรือแบบจำลองสนทนาเริ่มต้น และแปลงแบบจำลองเป็นอินเทอร์เฟซที่เรียกใช้งานได้ ระบบจึงไม่ผูกการสร้างคำตอบไว้กับผู้ให้บริการรายเดียว และสามารถควบคุมการเรียกใช้ผ่านกลไกจำกัดภาระงานพร้อมบันทึกข้อมูลการใช้งานของแบบจำลองได้

การสร้างคำตอบหลักดำเนินการโดยให้แบบจำลองใช้ข้อมูลจากคลังความรู้ พร้อมกำหนดให้ระบุระดับความครอบคลุมของข้อมูล หากการตั้งค่าการค้นเว็บเป็นแบบอัตโนมัติและพบว่าคลังความรู้ครอบคลุมคำถามไม่ครบ ระบบจึงดำเนินขั้นตอนค้นเว็บเพิ่มเติม ส่วนการตั้งค่าแบบปิดจะจำกัดคำตอบให้อ้างอิงคลังความรู้เป็นหลัก และการตั้งค่าแบบเปิดใช้การค้นเว็บเพื่อสนับสนุนคำตอบตามที่ผู้ใช้เลือก การค้นเว็บใช้เครื่องมือของแบบจำลองที่รองรับ และระบบจะไม่ถือว่าข้อมูลจากเว็บเป็นส่วนหนึ่งของคลังเอกสารรายวิชา

## 3.9.3 การจัดการเซสชันและส่วนติดต่อผู้ใช้งาน

ผู้ใช้โต้ตอบกับ KMITL RAG AI ได้ทั้งผ่านวิดเจ็ตในหน้าคอมมูนิตี้และหน้าถาม–ตอบแบบเต็ม ส่วนติดต่อผู้ใช้งานเลือกขอบเขตการค้นหาได้ เช่น คลังรายวิชาที่ผู้ใช้เป็นสมาชิก เอกสารเฉพาะ คลังส่วนบุคคล หรือโหมดค้นหาอัตโนมัติ ผู้ใช้สามารถเลือกถามเป็นคำถามเดี่ยวหรือเริ่มเซสชันที่รักษาบริบทจากข้อความก่อนหน้าได้ ทั้งนี้ระบบตรวจสอบสิทธิ์และขอบเขตที่เลือกซ้ำในฝั่งเซิร์ฟเวอร์ ไม่อาศัยข้อมูลจากส่วนติดต่อผู้ใช้งานเพียงอย่างเดียว

การใช้แต้มและโควตาของเซสชันแยกจากประวัติการสนทนา คำถามเดี่ยวมีค่าใช้จ่ายเริ่มต้น 1 แต้มต่อคำถามและไม่ส่งประวัติเดิมเข้าเป็นบริบทของแบบจำลอง ส่วนการเริ่มเซสชันมีค่าใช้จ่ายเริ่มต้น 4 แต้มและได้รับโควตา 5 ข้อความ โดยนำข้อความก่อนหน้าในเซสชันมาเป็นบริบท ตารางที่ใช้จริงในสคีมาปัจจุบันคือ `rag_credit_sessions` ซึ่งเก็บรหัสเซสชัน ผู้ใช้ จำนวนข้อความที่ยังใช้ได้ และข้อความสำหรับบริบทของเซสชัน โดยมีการย้ายชื่อจาก `rag_sessions` ในกระบวนการปรับปรุงสคีมา เมื่อส่งข้อความ ระบบลดโควตาด้วยคำสั่งปรับปรุงแบบมีเงื่อนไขว่าต้องยังมีข้อความคงเหลือ เพื่อไม่ให้คำขอที่เกิดพร้อมกันใช้โควตาสุดท้ายซ้ำได้ หากการสร้างคำตอบล้มเหลว ระบบคืนโควตาที่สำรองไว้ และคืนแต้มที่หักไปตามกรณี

เพื่อให้ผู้ใช้กลับมาอ่านหรือดำเนินบทสนทนาต่อในหน้าจอได้ ระบบจัดเก็บประวัติในตาราง `rag_conversations` และ `rag_messages` แยกจากตารางโควตา คำถามเดี่ยวและข้อความในเซสชันสามารถสร้างหรือเพิ่มรายการคำถามและคำตอบในประวัติได้ โดยระเบียนบทสนทนาผูกกับเจ้าของ มีชื่อบทสนทนาและป้ายกำกับขอบเขต ส่วนข้อความบันทึกบทบาท เนื้อหา เวลา และข้อมูลประกอบคำตอบ เช่น รายการแหล่งอ้างอิง โหมดการค้นเว็บ สถานะการใช้แต้ม และจำนวนโควตาที่เหลือ ทั้งนี้ ประวัติที่จัดเก็บในบทสนทนาใช้สำหรับแสดงและจัดการประวัติ ส่วนบริบทที่ส่งให้แบบจำลองในคำขอใหม่มาจากข้อความใน `rag_credit_sessions` เฉพาะเมื่อผู้ใช้กำลังใช้เซสชัน การอ่าน เปลี่ยนชื่อ และลบบทสนทนาตรวจสอบเจ้าของก่อนดำเนินการ และจำกัดจำนวนบทสนทนาที่แสดงกับจำนวนข้อความที่โหลดเพื่อควบคุมขนาดข้อมูล

คำตอบจากคลังความรู้แสดงการอ้างอิงในเนื้อหาด้วยหมายเลข เช่น `[1]` และส่งรายการ `citations` กลับไปยังส่วนติดต่อผู้ใช้งานเพื่อแสดงชื่อเอกสารและข้อความที่เกี่ยวข้อง ส่วนแหล่งข้อมูลจากการค้นเว็บแยกเป็น `web_sources` และอ้างอิงด้วยหมายเลขรูปแบบ `[W1]` เพื่อให้แยกที่มาของข้อมูลทั้งสองประเภทได้ชัดเจน ระบบตรวจสอบหมายเลขอ้างอิงกับรายการแหล่งข้อมูลที่มีอยู่ก่อนนำเสนอ โดยไม่กำหนดให้แบบจำลองสร้างบรรณานุกรมขึ้นเอง ส่วนติดต่อผู้ใช้งานจึงสามารถแสดงคำตอบพร้อมรายการแหล่งที่มาและบริบทของการค้นหาให้ผู้ใช้ตรวจสอบย้อนกลับได้
