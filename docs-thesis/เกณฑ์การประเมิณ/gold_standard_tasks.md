# ชุดภารกิจและเฉลยอ้างอิง (Gold Standard)

เอกสารนี้เป็นชุดทดสอบควบคุมฉบับตั้งต้นสำหรับตรวจการค้นคืนและคำตอบของ KMITL RAG AI และเป็นคู่มือกำหนดเฉลยของภารกิจค้นข้อมูล ต้องตรวจสอบแหล่งข้อมูลและอนุมัติเกณฑ์ก่อนเก็บข้อมูลจริง

## 1. ขอบเขตและวิธีเตรียมชุดทดสอบ

ชุดคำถาม RAG ด้านล่างอ้างอิงเนื้อหาใน [บทที่ 3.4 ระบบผู้ช่วยอัจฉริยะ KMITL RAG AI](../บทที่%203/section_3_4_kmitl_rag_ai.md) โดยใช้หัวข้อย่อยเป็นตำแหน่งหลักฐาน ไม่ระบุเลขหน้าเพราะไฟล์ต้นทางที่ใช้จัดทำชุดนี้ไม่มีเลขหน้า

ก่อนทดลอง:

1. นำเอกสารอ้างอิงฉบับที่กำหนดไว้ในตารางเข้าสู่คลังทดสอบหรือ notebook แยกเฉพาะ และตรวจว่าสถานะเอกสารพร้อมค้นคืนแล้ว
2. ทดสอบคำถามในโหมดที่ขอบเขตความรู้ชัดเจน ปิดการค้นเว็บถ้าต้องการวัดเฉพาะการค้นจากเอกสาร และบันทึกการตั้งค่าระบบ/แบบจำลองที่ใช้
3. ในแบบบันทึกจริง ให้แทนตำแหน่งหลักฐานระดับหัวข้อด้วยชื่อเอกสารและเลขหน้าหรือแหล่งอ้างอิงที่ระบบแสดงได้จริง ห้ามสร้างเลขหน้าหรือ citation ขึ้นเอง
4. หากวัตถุประสงค์คือประเมินการเข้าถึงเอกสารรายวิชา ให้เพิ่มเอกสารรายวิชาที่ได้รับอนุญาตและจัดทำเฉลยใหม่สำหรับเอกสารเหล่านั้น ชุดบทที่ 3 นี้ใช้เป็นชุดทดสอบ KMITL RAG AI/โครงการ ไม่ใช่ตัวแทนเอกสารรายวิชาทั้งหมด

## 2. ชุดคำถาม RAG และเฉลย

ให้ส่งคำถามตามข้อความในคอลัมน์ “คำถามทดสอบ” โดยไม่แสดงเฉลยแก่ผู้เข้าร่วม

| รหัส | คำถามทดสอบ | ประเด็นคำตอบที่ต้องมี | ตำแหน่งหลักฐานในเอกสารอ้างอิง |
|---|---|---|---|
| RAG-01 | MariaDB และ SurrealDB ใช้จัดเก็บข้อมูลประเภทใดในระบบ KMITL RAG AI? | MariaDB จัดเก็บข้อมูลกำกับเอกสาร ธุรกรรม และประวัติสนทนา; SurrealDB จัดเก็บ notebook, source, source embedding และข้อมูลที่เกี่ยวข้องกับการค้นคืน/ผลลัพธ์ AI | บทนำ 3.4; 3.4.2.1 |
| RAG-02 | ผู้ใช้เพิ่มเนื้อหาเข้าสู่คลังความรู้ได้ด้วยวิธีใด และเลือกจัดเก็บไว้ที่ใดได้บ้าง? | นำเข้าได้ทั้งไฟล์ URL หรือข้อความ; เลือกคลังส่วนบุคคลหรือคลังรายวิชา; ระบบบันทึก metadata และสถานะเริ่มต้น `processing` ก่อนสกัดเนื้อหา/สร้างเวกเตอร์ | 3.4.1.1 |
| RAG-03 | เมื่อผู้ใช้ถามคำถาม ระบบค้นคืนบริบทจากคลังที่เลือกอย่างไร? | ตรวจตัวตนและสิทธิ์; กำหนด notebook/source ในขอบเขตที่อนุญาต; สร้าง query embedding; ค้นเวกเตอร์ด้วย Cosine Similarity และกรองผลตาม similarity threshold | 3.4.1.2 |
| RAG-04 | หากผู้ใช้เลือกขอบเขตรายวิชาเฉพาะ ระบบจะไปค้นข้อมูลจากคลังอื่นแทนหรือไม่? | ไม่ค้นข้ามไปยังคลังอื่นโดยอัตโนมัติ; ค้นเฉพาะ notebook/source ที่ผู้ใช้มีสิทธิ์ในขอบเขตที่เลือก เพื่อป้องกันข้อมูลข้ามรายวิชารั่วไหล | 3.4.1.2 หัวข้อ Scope-constrained Search |
| RAG-05 | หากไม่พบชิ้นข้อความที่ผ่านเกณฑ์ ระบบควรทำอย่างไร? | ส่งผลค้นคืนว่าง/แจ้งว่าไม่มีบริบทสำหรับสังเคราะห์คำตอบ; ไม่ควรแต่งคำตอบเสมือนมีหลักฐานจากเอกสาร | 3.4.1.2 |
| RAG-06 | ระบบแสดงแหล่งอ้างอิงของคำตอบในรูปแบบใด? | แหล่งจากคลังเอกสารอาจแสดงเป็น `[1]`, `[2]`; แหล่งจากเว็บใช้ `[W1]` เมื่อมีการค้นเว็บ; แหล่งที่อ้างต้องรองรับข้อความคำตอบจริง | 3.4.1.2; 3.4.3.1 |
| RAG-07 | หากบริการแบบจำลองตอบล้มเหลวหลังมีการหักแต้ม/เครดิต ระบบจัดการอย่างไร? | บันทึกข้อผิดพลาด; คืนเครดิตหรือแต้มที่หักไปตามกรณีโดยเพิ่มรายการคืนที่อ้างอิงธุรกรรมเดิม ไม่ลบรายการหักเดิม; แจ้งผลแก่ Client | 3.4.2.3; 3.4.3.1 |
| RAG-08 | เอกสารอ้างอิงชุดนี้ระบุวันสอบกลางภาคของรายวิชาหรือไม่? | ไม่มีข้อมูลวันสอบในเอกสารอ้างอิงชุดนี้; คำตอบที่ยอมรับต้องระบุว่าเอกสารที่ค้นได้ไม่ให้ข้อมูลดังกล่าว และไม่คาดเดาวันสอบ | ตรวจทั้งเอกสารอ้างอิงที่โหลดในชุดควบคุม; ไม่มีตำแหน่งหลักฐานเชิงบวก |

### แนวคำตอบอ้างอิงแบบย่อ

- **RAG-01:** MariaDB ใช้กับข้อมูลกำกับเอกสาร ธุรกรรม และประวัติสนทนา ส่วน SurrealDB ใช้กับ notebook, source, source embedding และข้อมูลการค้นคืนที่เกี่ยวข้อง
- **RAG-02:** เพิ่มได้ด้วยไฟล์ URL หรือข้อความ และเลือกคลังส่วนบุคคล/คลังรายวิชาได้ ระบบสร้างระเบียน metadata สถานะ `processing` ก่อนเริ่มประมวลผล
- **RAG-03:** ระบบตรวจสิทธิ์และขอบเขตความรู้ สร้าง embedding ของคำถาม แล้วค้นเวกเตอร์ใน source ที่อนุญาตด้วย Cosine Similarity พร้อมกรองผลตามเกณฑ์
- **RAG-04:** ไม่ค้นข้ามคลังที่เลือกโดยอัตโนมัติ ค้นเฉพาะแหล่งที่ผู้ใช้ได้รับอนุญาตในขอบเขตนั้น
- **RAG-05:** เมื่อไม่มีบริบทที่ผ่านเกณฑ์ ระบบรายงานผลค้นคืนว่าง ไม่สังเคราะห์ข้อเท็จจริงที่ไม่มีหลักฐาน
- **RAG-06:** ใช้หมายเลขอ้างอิง เช่น `[1]`, `[2]` สำหรับแหล่งเอกสาร และ `[W1]` สำหรับแหล่งเว็บเมื่อมีการค้นเว็บ โดย citation ต้องรองรับข้อความที่อ้าง
- **RAG-07:** บันทึกข้อผิดพลาด คืนแต้ม/เครดิตที่เกี่ยวข้องเป็นธุรกรรมคืน และแจ้งผู้ใช้ ไม่ลบประวัติการหักเดิม
- **RAG-08:** เอกสารชุดควบคุมไม่ระบุวันสอบ จึงควรตอบว่าไม่มีข้อมูลในเอกสาร ไม่ควรเดาคำตอบ

## 3. เกณฑ์ตรวจคำตอบรายข้อ

ผู้ประเมินตรวจผลของแต่ละคำถามแยกเป็นสามส่วน:

1. **ความถูกต้องและความครบถ้วน:** ทำเครื่องหมายแต่ละประเด็นคำตอบที่ต้องมีว่า พบ/ไม่พบ และบันทึกข้อความที่ขัดกับเอกสาร
2. **การรองรับด้วยหลักฐาน:** ตรวจว่า citation ที่ระบบแสดงเปิดไปยังเอกสารและข้อความที่รองรับข้อกล่าวอ้างจริง หากอ้างผิดแหล่งหรือไม่มีหลักฐานให้บันทึกว่าไม่ผ่านด้านหลักฐาน
3. **การกล่าวอ้างเกินหลักฐาน:** ทำเครื่องหมาย “พบ” เมื่อมีข้อเท็จจริงสำคัญที่ขัดกับเอกสารหรือไม่มีหลักฐานรองรับ สำหรับ RAG-08 ให้ถือว่าการเดาวันสอบเป็นข้อกล่าวอ้างไร้หลักฐาน

ให้ถือว่าคำตอบหนึ่งข้อ **ผ่านความถูกต้องพร้อมหลักฐาน** เมื่อประเด็นสำคัญครบ ถูกต้อง มีแหล่งอ้างอิงที่รองรับ และไม่มีข้อกล่าวอ้างสำคัญที่ขัดแย้งหรือไร้หลักฐาน สำหรับ RAG-08 ให้ผ่านเมื่อระบบระบุข้อจำกัดของเอกสารโดยไม่แต่งคำตอบ ทั้งนี้ให้เก็บคะแนนความครบถ้วนแยกรายข้อไว้ด้วย ไม่รายงานเพียงคะแนนรวม

คำนวณอัตราคำตอบถูกต้องโดยใช้จำนวนคำถามที่ผ่านครบตามเกณฑ์หารด้วยจำนวนคำถามที่ทดสอบทั้งหมด ส่วนอัตราคำตอบที่มีข้อความไร้หลักฐานให้นับคำตอบที่มีข้อกล่าวอ้างสำคัญไร้หลักฐานอย่างน้อยหนึ่งรายการ แล้วหารด้วยจำนวนคำตอบทั้งหมด ใช้นิยามและเกณฑ์ที่ได้รับอนุมัติในแผนประเมิน

## 4. เฉลยภารกิจค้นหาและการเข้าถึงเอกสาร

ภารกิจค้นหาในแผนประเมินต้องผูกกับเอกสารที่อยู่ในคลังทดลองจริง จึงห้ามกำหนดชื่อรายวิชา ชื่อไฟล์ หรือสิทธิ์จากการคาดเดา ก่อนทดลอง ผู้จัดทำต้องกรอกข้อมูลในตารางต่อไปนี้และให้ผู้เชี่ยวชาญตรวจสอบเอกสารเป้าหมาย:

| รหัสภารกิจ | โจทย์ที่อ่านให้ผู้เข้าร่วม | คลัง/รายวิชาที่เลือก | เอกสารเป้าหมายและเลขหน้า/ตำแหน่ง | คำตอบหรือข้อมูลที่ผู้ใช้ต้องระบุ | สิทธิ์ผู้ทดสอบ | เงื่อนไขสำเร็จ |
|---|---|---|---|---|---|---|
| SRCH-01 | ค้นหาเอกสารที่มีข้อมูลเกี่ยวกับหัวข้อที่ผู้จัดทำกำหนดในรายวิชาที่ระบุ | กรอกก่อนทดสอบ | กรอกชื่อจริง/เลขหน้า | ระบุชื่อเอกสารและข้อมูลสำคัญตามเฉลย | บัญชีที่มีสิทธิ์ในรายวิชา | เปิดเอกสารเป้าหมายถูกต้องและตอบข้อมูลตามเฉลย |
| SRCH-02 | ค้นข้อมูลด้วยคำค้นหาหรือตัวกรองที่กำหนด แล้วเลือกผลลัพธ์ที่ตรงกับโจทย์ | กรอกก่อนทดสอบ | กรอกชื่อจริง/เลขหน้า | ระบุว่าผลลัพธ์ตรงกับเงื่อนไขใด | บัญชีที่มีสิทธิ์ในรายวิชา | เลือกเอกสารที่ตรงกับเฉลย ไม่ใช่เพียงเอกสารชื่อคล้าย |
| SRCH-03 | ถามคำถามที่มีคำตอบอยู่ในเอกสารเป้าหมายและเปิดแหล่งอ้างอิงเพื่อตรวจสอบ | กรอกก่อนทดสอบ | กรอกชื่อจริง/เลขหน้า | บันทึกคำตอบหลักและข้อความที่รองรับ | บัญชีที่มีสิทธิ์ในรายวิชา | คำตอบถูกต้องและเปิดแหล่งที่รองรับได้ |

**วิธีตัดสิน:** ให้ถือว่าสำเร็จเมื่อผู้เข้าร่วมระบุหรือเปิดเอกสารเป้าหมายตามเฉลยและเข้าถึงได้ด้วยสิทธิ์ของบัญชีนั้น หากผู้เข้าร่วมเปิดเอกสารผิด ตอบจากเอกสารอื่น หรือได้รับคำใบ้ที่บอกคำตอบ ให้ลงผลไม่สำเร็จตามกติกาในแบบบันทึกภารกิจ พร้อมบันทึกพฤติกรรมที่เกิดขึ้นจริง

## 5. การตรวจสอบสิทธิ์แยกจากผลภารกิจผู้ใช้

ใช้บัญชีทดสอบอย่างน้อยสองระดับสิทธิ์และเอกสารทดสอบที่ทราบเจ้าของ/ขอบเขตแน่นอน ห้ามใช้ข้อมูลจริงที่ผู้ทดสอบไม่มีสิทธิ์เข้าถึง

| รหัส | บัญชี/ขอบเขตที่ทดสอบ | การกระทำ | ผลที่คาดหวัง | ผลจริง | ผ่าน/ไม่ผ่าน |
|---|---|---|---|---|---|
| ACL-01 | บัญชีที่มีสิทธิ์ในคลังเป้าหมาย | ค้นและเปิดเอกสารที่ได้รับอนุญาต | พบและเปิดเอกสารได้ |  |  |
| ACL-02 | บัญชีที่ไม่มีสิทธิ์ในคลังเป้าหมาย | ค้นหรือถามเพื่อดึงเนื้อหาจากคลังนั้น | ปฏิเสธ/ไม่คืนเนื้อหาหรือ citation จากคลังที่ไม่มีสิทธิ์ |  |  |
| ACL-03 | บัญชีที่เลือกคลัง/รายวิชา A ซึ่งได้รับอนุญาต | ถามคำถามที่มีคำตอบเฉพาะในคลัง/รายวิชา B | ไม่ดึงข้อมูลจาก B โดยอัตโนมัติ; แจ้งว่าไม่มีหลักฐานในขอบเขตที่เลือก |  |  |

รายงานผล ACL แยกจาก Task Success Rate และคะแนนความถูกต้องของคำตอบ หากพบการเปิดเผยข้อมูลข้ามสิทธิ์แม้หนึ่งกรณี ให้รายงานเป็นข้อบกพร่องสำคัญ ไม่เฉลี่ยรวมกับกรณีที่ผ่าน
