# 2.7 ระบบการจัดการฐานข้อมูล

## 2.7.1 ฐานข้อมูลแบบมัลติโมเดลและ Polyglot Persistence

ฐานข้อมูลแบบมัลติโมเดล (Multi-Model Database) รองรับการแทนข้อมูลหลายรูปแบบ เช่น เชิงสัมพันธ์ เอกสาร กราฟ หรือเวกเตอร์ ส่วน Polyglot Persistence คือการเลือกใช้ฐานข้อมูลต่างชนิดร่วมกัน โดยให้แต่ละระบบรับผิดชอบข้อมูลที่เหมาะกับความสามารถของตน Ye และคณะ (2023) เป็นแหล่งอ้างอิงเกี่ยวกับการจัดการข้อมูลแบบหลายโมเดลและการคงอยู่ของข้อมูลหลายชนิด

สถาปัตยกรรมของแพลตฟอร์มใช้ MariaDB สำหรับข้อมูลเชิงสัมพันธ์และธุรกรรม เช่น ผู้ใช้ ห้องเรียน สมาชิก โพสต์ ปฏิสัมพันธ์ และสมุดบัญชีแต้ม ใช้ SurrealDB สำหรับ notebook, source, source embedding, ข้อมูลเชิงความสัมพันธ์ และเซสชัน Quiz/Roadmap ที่อยู่ในระบบหลัก ส่วน Redis สนับสนุนการแคช และบริการ PocketBase มีฐานข้อมูลภายในสำหรับแอป Roadmap แบบ standalone การเลือกฐานข้อมูลตามหน้าที่ช่วยหลีกเลี่ยงการบังคับข้อมูลทุกชนิดให้อยู่ในแบบจำลองเดียว

แม้แนวคิดฐานข้อมูลมัลติโมเดลอาจหมายถึงเอนจินเดียวที่รองรับข้อมูลหลายรูปแบบ แต่ implementation นี้ใช้ทั้ง SurrealDB และ MariaDB จึงควรอธิบายว่าเป็นสถาปัตยกรรมแบบผสมผสานหรือ Polyglot Persistence ที่มี SurrealDB รองรับข้อมูลเอกสาร กราฟ และเวกเตอร์ ร่วมกับ MariaDB สำหรับข้อมูลธุรกรรม ไม่ควรระบุว่าบัญชีผู้ใช้ รายวิชา และเวกเตอร์ทั้งหมดถูกจัดเก็บใน SurrealDB เพียงฐานเดียว

การเชื่อมโยงข้ามฐานข้อมูลอาศัยรหัสอ้างอิงเชิงตรรกะที่จัดการในชั้นแอปพลิเคชัน เช่น `users.library_notebook_id` และ `rooms.library_notebook_id` ชี้ไปยัง notebook ส่วน `library_documents.notebook_id` และ `source_id` เชื่อมข้อมูลกำกับใน MariaDB กับ notebook และ source ใน SurrealDB ความสัมพันธ์เหล่านี้ไม่ได้ถูกบังคับเป็น SQL foreign key ข้ามเอนจิน จึงต้องตรวจสอบความเป็นเจ้าของ สิทธิ์ และการมีอยู่ของระเบียนใน service/repository ก่อนใช้งาน
