# 2.6 ทฤษฎีการออกแบบประสบการณ์ผู้ใช้และส่วนติดต่อผู้ใช้งาน

## 2.6.1 การออกแบบโดยมีผู้ใช้เป็นศูนย์กลาง

การออกแบบโดยมีผู้ใช้เป็นศูนย์กลาง (User-Centered Design: UCD) เริ่มจากการทำความเข้าใจผู้ใช้ งานที่ต้องทำ และบริบทแวดล้อม แล้วนำข้อมูลดังกล่าวมาพัฒนาและประเมินส่วนติดต่อให้สอดคล้องกับความต้องการ Hassenzahl (2026) กล่าวถึงประสบการณ์ผู้ใช้และการออกแบบประสบการณ์โดยให้ความสำคัญกับเป้าหมายและความต้องการของผู้ใช้

แพลตฟอร์มมีผู้ใช้หลักหลายบทบาท ได้แก่ นักศึกษา ผู้สอน และผู้ดูแลระบบ จึงต้องจัดวางข้อมูลและคำสั่งให้สอดคล้องกับงานของแต่ละกลุ่ม นักศึกษาต้องเข้าถึงฟีด ห้องเรียน คลังความรู้ และบริการ AI ได้สะดวก ผู้สอนต้องจัดการเนื้อหาห้องและเอกสารประกอบการสอน ส่วนผู้ดูแลต้องเข้าถึงการกำหนดค่าหรือการจัดการระบบตามสิทธิ์ หลัก UCD เชื่อมโยงกับการลดขั้นตอนที่ไม่จำเป็น การให้ข้อมูลย้อนกลับเมื่อระบบกำลังประมวลผล และการแสดงข้อผิดพลาดในรูปแบบที่ช่วยให้ผู้ใช้แก้ไขได้

## 2.6.2 ส่วนติดต่อผู้ใช้ตามหลักการออกแบบและสถาปัตยกรรมสารสนเทศ

Material Design 3 และ Apple Human Interface Guidelines เป็นแนวทางที่รวบรวมหลักการออกแบบองค์ประกอบ การนำทาง การตอบสนอง และการเข้าถึงของส่วนติดต่อ (Google, 2024; Apple, 2024) ขณะที่ Yablonski (2024) อธิบายกฎและหลักการด้านประสบการณ์ผู้ใช้ซึ่งช่วยจัดลำดับข้อมูล ลดภาระการตัดสินใจ และทำให้การใช้งานคาดการณ์ได้

หน้าคอมมูนิตี้ประยุกต์การจัดวางแบบสามคอลัมน์บนจอขนาดใหญ่ ได้แก่ แถบนำทางด้านซ้าย พื้นที่ฟีดหลักตรงกลาง และแผงสถานะหรือแต้มด้านขวา เมื่อหน้าจอมีขนาดเล็ก ระบบปรับเป็นคอลัมน์เดียวและใช้เมนูแบบแผงเลื่อนเพื่อคงพื้นที่อ่านเนื้อหา โครงสร้าง Information Architecture แบ่งมุมมองตามงาน เช่น ฟีดสาธารณะ รายวิชาที่เข้าร่วม รายการบันทึก และคลังสื่อ ช่วยให้ผู้ใช้ระบุจุดเริ่มต้นและบริบทของงานได้

การจัดสีและการแยกบทบาทในส่วนติดต่อควรพิจารณาความชัดเจนและความสม่ำเสมอร่วมกัน ใน implementation ปัจจุบันใช้ธีม SIET Pink ร่วมกัน ไม่พบชุดสีแยกเฉพาะผู้สอนและนักศึกษา การแยกบทบาทจึงแสดงผ่านเมนู ป้ายกำกับ และคำสั่งที่ผู้ใช้ได้รับอนุญาต ขณะที่ backend ยังคงตรวจสิทธิ์อีกชั้นหนึ่ง สีเพียงอย่างเดียวไม่ถือเป็นกลไกควบคุมการเข้าถึง
