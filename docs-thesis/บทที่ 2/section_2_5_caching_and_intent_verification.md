# 2.5 ระบบแคชและการตรวจสอบความถูกต้องของเจตนา

## 2.5.1 กลยุทธ์การทำแคชระดับคำตอบ

การแคชผลลัพธ์ของ LLM ช่วยลดเวลาแฝงและลดจำนวนครั้งที่ต้องเรียกบริการโมเดลเมื่อมีคำถามหรือบริบทที่เคยประมวลผลแล้ว Bang และคณะ (2023) ศึกษาการประเมินโมเดลในด้านการให้เหตุผล ภาพหลอน และปฏิสัมพันธ์ ซึ่งเกี่ยวข้องกับความจำเป็นในการคำนึงถึงคุณภาพของคำตอบก่อนนำผลลัพธ์เดิมกลับมาใช้ ส่วนการจับคู่แบบตรงทุกประการ (Exact Cache) และการจับคู่เชิงความหมาย (Semantic Cache) เป็นกลยุทธ์ทางวิศวกรรมที่ใช้ลดการเรียกซ้ำ โดยต้องคำนึงถึงขอบเขตบริบทและความถูกต้องของคำตอบที่จัดเก็บ

Exact Cache ของระบบ Notebook Answer Cache ทำ normalization คำถามและสร้างคีย์ด้วย SHA-256 ซึ่งย่อผลลัพธ์เป็นส่วนหนึ่งของคีย์ โดยผูกกับขอบเขตความรู้ ภาษา และ fingerprint ของบริบทเพื่อป้องกันการนำคำตอบจากคลังหรือภาษาหนึ่งไปใช้กับอีกขอบเขตหนึ่ง ส่วนเส้นทาง KMITL RAG แบบถามรวดเร็วมีแคชเฉพาะของตนเอง โดยคำนวณคีย์จากคำถาม ขอบเขต notebook/source โหมดค้นเว็บ ภาษา และโมเดล การเรียกซ้ำในเซสชันที่มีประวัติสนทนาไม่ได้ใช้แคชแบบเดียวกับคำถามเดี่ยว

Semantic Cache ฝังคำถามเป็นเวกเตอร์แล้วเปรียบเทียบกับคำถามในดัชนีแคชด้วย Cosine Similarity ค่าเริ่มต้นกำหนดเกณฑ์สูงที่ 0.97 และเกณฑ์ระดับกลางที่ 0.92 โดยเกณฑ์สามารถเปลี่ยนตามการตั้งค่าหรือกลไกปรับค่าได้ เมื่อค่าความคล้ายคลึงถึงเกณฑ์สูง ระบบนำคำตอบกลับมาใช้ได้โดยตรง ส่วนผลระดับกลางต้องผ่านการตรวจสอบเจตนาก่อน ส่วนผลต่ำกว่าระดับกลางถือเป็น cache miss และสร้างคำตอบใหม่ เกณฑ์เหล่านี้เป็นค่าปริยายของระบบ ไม่ใช่ค่ามาตรฐานสากลที่เหมาะกับทุกชุดข้อมูล

## 2.5.2 การตรวจสอบเจตนาของผู้ใช้และกลไกป้องกัน

คำถามสองรายการอาจมีถ้อยคำคล้ายกันแต่ต้องการคำตอบคนละข้อเท็จจริง เช่น ระบุปี จำนวน บุคคล สถานที่ หรือการปฏิเสธที่ต่างกัน การใช้ LLM-as-a-Judge จึงช่วยประเมินว่าคำถามใหม่และคำถามที่ถูกแคชไว้ต้องการคำตอบชนิดเดียวกันหรือไม่ แนวทางประเมินผลลัพธ์ของโมเดลโดยโมเดลภาษาได้รับการศึกษาโดย Zheng และคณะ (2023) ในระบบนี้ตัวตรวจสอบรับคำถามเดิมและคำถามใหม่ พร้อม intent/entity ที่สกัดไว้ แล้วให้ผล JSON แบบ boolean ว่ามีเจตนาเดียวกันหรือไม่ หากข้อมูลไม่ครบ ผลไม่ถูกต้อง หรือหมดเวลา ระบบเลือกสร้างคำตอบใหม่แทนการใช้ cache candidate

การเรียกโมเดลสำหรับตรวจเจตนาเป็นบริการเสริมที่อาจล่าช้าหรือขัดข้อง Circuit Breaker ตามแนวคิดด้านความทนทานของสถาปัตยกรรมซอฟต์แวร์ (Dehghani, 2021) ช่วยหยุดการเรียกตรวจซ้ำเมื่อเกิดข้อผิดพลาดต่อเนื่อง ระบบมีสถานะ Closed, Open และ Half-Open เมื่อวงจรเปิดจะข้ามขั้นตรวจเจตนาและกลับไปสร้างคำตอบใหม่ เมื่อครบช่วงพักจะทดลองคำขอจำนวนจำกัดเพื่อพิจารณากลับสู่สถานะปกติ กลไกนี้ป้องกันไม่ให้บริการตรวจแคชที่มีปัญหากลายเป็นจุดล้มเหลวของการตอบคำถามหลัก
